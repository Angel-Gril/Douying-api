# 解析原理与开发测试

本文只记录本项目自身的解析原理、数据约定、下载逻辑及开发验证。

## 链接进入解析器的过程

1. 从分享文案提取 HTTP(S) 链接，使用真实主机名识别平台。
2. 短链只在对应平台的站点范围内逐跳展开，保留解析所需的分享参数。
3. 优先调用本项目的平台原生解析器；未取得可用资源时进入对应平台的备用适配器。
4. 所有来源最终返回相同的数据结构。无有效资源时返回失败，不仅凭 HTTP 200 判断解析成功。

## 统一数据约定

| 字段 | 含义 |
|---|---|
| `type` | `video` 视频、`image` 图集、`live` 实况图片与动态视频 |
| `url` | 当前默认媒体地址 |
| `duration` | 毫秒；未知为 0 |
| `data_size` | 文件字节数；未知为 0 |
| `bit_rate` / `bitrate` | bit/s；不把文件字节数当作码率 |
| `video_backup` | 实际取得的全部可用视频档位，包含编码、宽高、帧率及各档备用 URL |
| `audio_url` / `audio_backup` | 配套音轨和可单独下载的音轨列表 |
| `requires_mux` | 当前视频是分离流，下载成片时需要合并音轨 |
| `segments` / `requires_concat` | 多段视频地址及拼接标记 |
| `images` | 静态图片地址列表 |
| `live_photo` | `image`、`video` 一一对应的实况资源列表 |
| `parts` | 分 P 的编号、标题、时长和可重新解析的链接 |
| `statistics` | 实际取得的播放、点赞、评论、收藏、分享等数字 |

备用适配器负责字段名称、作者结构、时间单位和列表形态转换，不把原生解析结果重复转换。无法确认的参数保持未知，不用估计值冒充实际信息。

## 抖音解析逻辑

- 先获取作品详情，再保留实际返回的全部转码档及同档备用地址。
- 原画使用媒体 `video_id` 构造 `ratio=default` 播放入口，与作品 ID 区分。
- HEAD 逐跳解析入口，验证最终媒体响应和体积；探测失败时保留已取得的转码，只有未验证入口时继续其他策略。
- 最高码率转码与原画分别处理。原画 HEAD 没有提供的宽高、帧率和码率不沿用转码值。
- 实况资源保留静态图片和动态视频配对，统计字段只取实际数字。
- 签名备用策略让请求 UA、签名 UA、设备参数保持一致，选择本地请求库支持的 TLS 指纹；手动会话不额外启动浏览器，也不因失败删除无关的自动缓存。
- 自动会话刷新采用共享锁，避免并发启动多个浏览器；状态查询只读取缓存状态，不主动刷新会话。

## 小红书与快手解析逻辑

- 小红书从页面嵌入数据中定位笔记，保留分享验证参数，收集实际存在的 H.264、H.265、AV1 流及备用 URL。
- 默认画质根据实际分辨率、码率与兼容性选择，不单凭编码名称认定画质更高。
- 笔记中的静态图片和动态片段整理成实况对；字段缺失时不补造分辨率、大小或音轨。
- 快手依次尝试原生响应、页面初始化数据、页面内嵌数据与引用对象，支持视频、图集及实际存在的媒体信息。
- 网络请求只接受对应平台主机和允许的跳转，会话信息不会跟随到其他站点。

## 哔哩哔哩解析逻辑

- 先查询作品与分 P 信息，再用选中分 P 的 `cid` 查询实际播放资源。
- 同时处理完整视频流与 DASH 音视频分离流。接口列出的候选画质不等于当前可下载画质，页面只展示实际返回的流。
- 默认优先完整视频；选择分离流时保留音轨配对并在服务器合并。多段资源先完整下载，再按顺序拼接。
- 媒体地址优先采用响应中真实存在的平台普通 HTTPS CDN，保留其他候选，不硬改域名。
- 分 P 由用户明确选择后重新解析，不自动下载全部分集。

## 下载逻辑

普通资源通过流式代理下载，按媒体来源选择 Referer，支持 Range / 206，并验证声明长度、字节范围与实际接收量。错误页、JSON、空文件和未验证播放清单不会作为视频保存。

图集 ZIP、分离音轨合并、多段拼接和未加密点播 HLS 使用下载任务。每个任务拥有独立临时目录；HLS 的跳转后清单地址作为相对路径基址，每个子清单、初始化片段和媒体分片都重新验证。媒体处理进程只读取下载后的本地文件，不接收任意网络输入，也不接收伪装成媒体的嵌套清单。

资源上限：每进程最多 3 个活动任务，普通打包/拼接最多 100 个资源，HLS 最多 500 个分片，单任务下载上限 4 GiB、执行上限 15 分钟，完成文件保留 10 分钟。当前任务状态保存在进程内，部署使用单 worker。

地址校验只接受支持平台控制的媒体域名、服务端明确配置的附加主机或公网 IP 字面量，拒绝任意外来域名及私网跳转。代理 DNS 的地址映射只对可信媒体主机生效。

页面进度来自实际字节数或服务端阶段，不使用固定延迟模拟完成。普通下载可以中止读取；处理任务可以取消并清理临时文件。页面内存路径限制为 256 MiB，大文件可交给浏览器管理；支持的浏览器可选择直接流式写入磁盘。

实况图提供照片和动态视频分别下载或 ZIP 打包，不把资源配对描述为重新生成手机原生实况格式。

## 开发验证

- 单元与接口：平台路由、字段单位、画质选择、统计、实况、分 P、分离音轨、备用降级和异常响应。
- 下载：平台请求头、Range、完整字节数、错误页拒绝、私网跳转拒绝、任务取消与文件清理。
- 媒体处理：真实生成的小型音视频用于合并验证，真实生成的点播清单用于 HLS 合并验证；加密、无限直播、错误字节范围与嵌套清单均有拒绝用例。
- Linux 媒体运行环境：相同 TS 点播样本在默认静态程序中异常退出，系统安装版本正常处理；部署与 CI 显式指定系统 FFmpeg，并保留真实 HLS 合并测试。
- 浏览器：全部画质、资源绑定、实况配对、ZIP、分 P 操作、音轨合并、进度、取消、错误恢复、移动端宽度与键盘操作。

运行：

```bash
python -m pytest -q
python -m compileall -q server.py douyin_parser.py bilibili_parser.py platform_parsers.py media_normalizer.py public_api.py media_downloads.py
```

本轮真实联调取得抖音 7 档视频资源并下载 2,432,219 字节的有效 MP4。哔哩哔哩取得 7 个视频档位、3 条音轨；选定分离流下载共 14,700,421 字节，合并产物 14,767,125 字节，确认同时含视频和音频。真实浏览器完成两种下载，无页面脚本错误；测试文件随后清理。

小红书已完成解析结构和跳转边界的自动化验证，本轮实站样本未取得有效媒体，实站效果尚待可访问内容复测。直接写磁盘的文件选择器交互尚未自动验证。备用网关的真实调用未纳入本轮实站结果，自动化测试覆盖其正常、失败与降级分支。
