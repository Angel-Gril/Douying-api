# 演示页与免费测试后端

## 网页和解析服务的关系

网页负责输入分享链接、展示画质和发起下载。实际作品请求、原画探测及下载转发由解析服务完成。GitHub Pages 可以托管网页；页面通过“解析服务设置”连接实际的 HTTPS 后端。

完整 FastAPI 服务和轻量测试入口使用同一个 `index.html`。完整服务默认连接本站接口；Pages 构建将网页标记为静态演示，初次打开时要求填写服务地址。地址经过格式和连接校验后只保存在当前浏览器，不放入分享参数。切换服务时清除旧解析结果，取消仍在等待的解析请求；存在活动下载时先取消下载，再切换服务。

## 免费测试入口的实现

`cloudflare/worker.py` 使用 Workers 的 Python 运行时和网络请求接口。作品 ID 提取、媒体字段、转码档位与实况格式化直接复用 `douyin_parser.py`，不复制第二份平台解析器。测试入口不加载完整服务中的浏览器、签名请求库或本地媒体处理程序。

| 能力 | 轻量测试入口 |
|---|---|
| 平台 | 抖音 HTTPS 分享链接及作品链接 |
| 视频画质 | 保留详情实际返回的所有档位与备用地址 |
| 原画 | 使用媒体 ID 构造原画入口，HEAD 展开和检查有效媒体及体积 |
| 2K / 4K | 返回对应档位时保留真实宽高；原画宽高未知时不虚构分辨率 |
| 图集与实况 | 返回静态图片、动态视频和配对信息 |
| 单个资源下载 | 流式转发，平台请求头、逐跳媒体主机检查及单段 Range |
| 下载限制 | 测试代理要求有效 Content-Length，单次最多 256 MiB |
| 浏览器及签名兜底 | 不提供；未取得资源时返回明确失败 |
| ZIP / 音视频合并 / 拼接 / HLS 合并 | 不提供，任务接口返回 501 |

原生接口的访问结果会随平台和请求节点变化。轻量入口没有取得媒体时，不伪造链接或画质，也不假设完整服务的所有策略都可用。

状态接口声明真实能力、支持平台和限制提示。网页据此展示平台范围、禁用不支持的任务，并保留可单独下载的资源。详情失败和媒体代理错误继续使用本项目的 `code/msg/data` 结构。

## 本地构建与验证

需要 Python、Node.js 和 npm。以下命令从项目根目录执行，Wrangler 固定版本以保持构建行为可重复：

```bash
npx --yes wrangler@4.151.1 --cwd cloudflare deploy --dry-run --outdir .dry-run
npx --yes wrangler@4.151.1 --cwd cloudflare dev --port 8789
```

本地页面为 `http://localhost:8789`，接口为 `/api/status`、`/api/parse` 和 `/api/download`。`cloudflare/build.py` 只把 Worker 入口、共享纯解析器和公开网页放入构建目录，原生模块、运行配置、会话缓存、参考目录、测试文件和日志不进入部署包。

Worker 配置使用对应兼容日期的内置 Python SDK。测试入口没有外部 Python 依赖，不需要安装完整服务的浏览器和媒体处理依赖。

```bash
python -m pytest -q tests/test_cloudflare.py tests/test_frontend.py
```

## 部署测试入口

可以先创建临时免费预览：

```bash
npx --yes wrangler@4.151.1 --cwd cloudflare deploy --temporary
```

命令完成后会输出网页和 API 共用的 HTTPS 测试地址。临时账号需要在命令提示的时间内通过官方页面认领，才能长期保留；认领链接属于账户操作信息，仅保存在操作者本地或私人会话，不写入版本库和网页。

使用自己的账号部署时，通过正常的浏览器登录流程连接账号：

```bash
npx --yes wrangler@4.151.1 login
npx --yes wrangler@4.151.1 --cwd cloudflare deploy
```

测试配置不使用容器、数据库、付费存储或浏览器服务，也不配置付费 CPU 上限。免费计划当前为每日 100,000 次请求、每次 10 ms CPU；等待网络不计入 CPU 时间，实际资源使用仍由平台限制，超过额度或执行限制时不能保证解析成功。

## GitHub Pages 网页

项目的 `.github/workflows/pages.yml` 仅发布生成的 `index.html` 和 `.nojekyll`，不上传整个项目。仓库 Pages 的 Source 设为 GitHub Actions 后，可由对应分支推送或手动运行工作流发布。

页面首次打开时，在“解析服务设置”填写测试入口的根地址，例如 `https://你的服务.你的子域.workers.dev`，点击“连接并保存”。不要添加 `/api`、路径、账号或查询参数。HTTPS 网页要求 HTTPS 后端。

跨站连接时，后端须允许网页来源。测试配置中的 `CORS_ORIGINS` 包含本仓库的 Pages 来源 `https://angel-gril.github.io`；来源不包含仓库路径。部署到其他网页域名时按实际来源修改配置后重新部署。

打开 Worker 自带网页时，页面与接口同源，无需另外配置地址。

## 开发验收记录

- 新增浏览器测试覆盖 Pages 初始待配置、连接校验、保存和刷新恢复、跨站解析与下载、清除地址、非法地址拒绝，以及受限后端的能力提示与任务禁用。
- Worker 行为测试覆盖平台主机、分享跳转、媒体重定向、凭据隔离、CORS、错误响应、2K/4K 结构样本、原画探测和 Range 转发。
- 本轮完整自动化测试 259 项通过；结构样本证明字段处理行为，不等于每条作品或所有节点均能取得对应资源。
- Workers 真实本地运行时和免费云端均解析同一条公开视频，取得原画与 7 个画质档位；Range 请求返回 206、1024 字节和有效 MP4 文件头，总文件长度为 2,432,219 字节。
- 真实 Chromium 从云端网页完成解析并保存完整的 2,432,219 字节 MP4；桌面与 390px 移动端布局已核对，无横向溢出和页面脚本错误。
- GitHub Pages 实际发布后，再由真实 Chromium 连接云端 Worker，完成相同作品的完整 MP4 下载；跨域连接、390px 移动布局和刷新后恢复服务地址均通过。GitHub Actions 同时通过完整测试和 Workers 部署包构建检查。
- 真实 2K/4K 作品专项下载尚未验证。小红书、B站和完整媒体处理能力继续由完整后端提供，不属于本轮轻量入口的实站结果。
