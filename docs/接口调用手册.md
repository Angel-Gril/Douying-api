# 接口调用手册

本文记录本项目的调用方式、实际响应约定、资源选择及下载流程。解析实现见 [解析原理与开发测试](解析原理与开发测试.md)，页面操作见 [使用说明](使用说明.md)，运行环境见 [部署指南](部署指南.md)。

本手册描述完整后端。免费 Workers 测试入口提供抖音直链解析和单资源下载，能力范围见 [演示页部署](演示页部署.md)；调用者可通过 `/api/status` 确认支持的平台和处理任务。

## 服务入口与接口清单

本地基础地址为 `http://127.0.0.1:8848`。服务启动后，`/docs` 提供交互式接口文档，`/openapi.json` 提供参数和请求模型定义。以下 curl 示例采用 Bash 换行语法；Windows 可在 WSL 中执行，或合并为单行并使用 `curl.exe`。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/parse` | 分享链接解析 |
| GET | `/api/download` | 单个媒体的流式代理 |
| POST | `/api/download/jobs` | 创建 ZIP、音视频合并、拼接或 HLS 任务 |
| GET | `/api/download/jobs/{id}` | 查询任务和真实进度 |
| DELETE | `/api/download/jobs/{id}` | 取消活动任务 |
| GET | `/api/download/jobs/{id}/file` | 下载已完成文件 |
| GET | `/api/status` | 查询运行状态及能力 |
| GET | `/api/test` | 开发用逐策略诊断，默认关闭 |
| GET | `/api/debug` | 开发用抖音媒体字段诊断，默认关闭 |

## 解析链接

`GET /api/parse` 只有一个必填查询参数 `url`，可以传作品链接或带链接的分享文案。短链和平台识别均由服务处理，不需要调用者先展开。

```bash
curl --get 'http://127.0.0.1:8848/api/parse' \
  --data-urlencode 'url=https://www.bilibili.com/video/BV1GJ411x7h7/?p=1'
```

分享地址中的 `&`、`?` 等字符应通过查询参数编码传入，不要手工拼接成第二组服务参数。

成功响应示意如下；字段是否存在及具体值以实际结果为准：

```json
{
  "code": 200,
  "msg": "解析成功",
  "platform": "bilibili",
  "data": {
    "type": "video",
    "title": "示例作品",
    "url": "https://media.example/video.mp4",
    "duration": 12000,
    "width": 1920,
    "height": 1080,
    "data_size": 0,
    "author": {"name": "作者", "id": "123", "avatar": ""},
    "video_backup": [],
    "audio_backup": [],
    "parts": []
  }
}
```

`media.example` 仅为说明字段结构的占位地址；调用下载接口时使用本次解析实际返回的地址。

| 字段 | 含义与处理方式 |
|---|---|
| `type` | `video`、`image` 或 `live` |
| `url` / `cover` | 默认视频和封面地址 |
| `title` / `desc` | 作品标题、描述；并非每个来源都有描述 |
| `author` | `name`、`id`、`avatar` |
| `duration` | 毫秒，未知为 0 |
| `width` / `height` | 像素，未知为 0 |
| `data_size` | 字节，未知为 0 |
| `bitrate` / `bit_rate` | bit/s；顶层字段因来源可能使用其中一种，视频档位使用 `bit_rate` |
| `fps` / `codec` / `format` | 帧率、编码、容器；未知值可能为 0 或空字符串 |
| `fps_kind` / `codec_tag` | 原画平均帧率标记 `average`，以及 `avc1`、`hvc1` 等实际样本描述标记 |
| `bitrate_kind` / `overall_bitrate` | `video_average` 表示视频轨平均码率；`overall_bitrate` 为另行计算的整文件平均码率，单位 bit/s |
| `video_duration` / `duration_source` | 原画视频轨媒体时长（毫秒）及顶层时长的媒体来源标记 |
| `rotation` / `metadata_source` | 已确认的视频轨旋转角度和 `mp4_moov` 元数据来源；缺失表示未确认 |
| `quality` | 当前资源的档位或 `original` 标记 |
| `video_backup` | 实际取得的全部视频档位，每项包含 `url`、`url_list` 及自身元数据 |
| `audio_url` / `audio_backup` | 默认音轨及可单独选择的音轨列表 |
| `requires_mux` | 视频为分离流，需要配合音轨合并 |
| `requires_concat` / `segments` | 需要将多个地址按顺序拼接 |
| `images` | 图片地址列表 |
| `live_photo` | 实况配对列表，每项为 `{image, video}` |
| `parts` | 分 P 列表，每项包含 `index`、`title`、`url`、`cid`、`duration` |
| `statistics` / `play_count` | 实际取得的统计数字；缺少字段与明确的 0 含义不同 |
| `source` | 本次采用的解析来源标记，用于本项目开发排查 |

### 画质、分 P 与实况的选择

读取 `video_backup` 后，使用所选项自身的 `url` 和元数据，不把顶层参数套到所有档位。`url_list` 保存同档备用地址；当前普通下载接口每次接收一个 URL，调用者可在失败后明确选择下一地址重试。

页面按视频宽高的短边识别画质：1440p 显示为 2K，2160p 显示为 4K；横竖屏均适用。没有宽高时才尝试读取档位名称中的分辨率。只有平台实际返回的档位可以下载，不将平台列出的候选画质当作已有资源。

抖音 `original_url` 为原画入口，正常解析先探测最终媒体地址和体积，再尽力通过有界 Range 取得原画自身元数据。成功时原画具有自己的宽高、编码和平均帧率，失败字段保持未知；`quality=original` 本身不表示已确认 4K，应结合实际分辨率判断。码率字段须区分视频轨与整文件平均值，读取预算和细节见 [原画元数据探测](原画元数据探测.md)。

B站需要切换分 P 时，将选中 `parts` 项的 `url` 再传入 `/api/parse`，然后下载新响应中的媒体。图集下载 `images`；实况可以分别下载 `live_photo` 中的照片和动态视频，或将地址列表交给 ZIP 任务。ZIP 是资源打包，不是手机原生实况格式转换。

## 单个媒体下载

查询参数：`url` 必填，为解析返回的媒体地址；`filename` 可选，默认 `video.mp4`，服务会清理非法文件名字符。

```bash
curl --get 'http://127.0.0.1:8848/api/download' \
  --data-urlencode 'url=<解析返回的媒体地址>' \
  --data-urlencode 'filename=video.mp4' \
  --dump-header download.headers --output video.mp4
```

成功返回媒体字节流和 `Content-Disposition: attachment`。下载音轨或图片时使用对应的文件名后缀；此接口不会转码，修改后缀也不会改变内容。

Range 示例：

```bash
curl --get 'http://127.0.0.1:8848/api/download' \
  --data-urlencode 'url=<解析返回的媒体地址>' \
  -H 'Range: bytes=0-1048575' --output first-part.bin
```

只支持单个字节范围；上游支持时返回 `206` 和经校验的 `Content-Range`。上游忽略 Range 时可能返回完整的 `200` 响应，调用者应检查响应而非直接追加。服务器会校验媒体类型、字节范围和传输长度，但响应开始后发生的中断无法改写成 JSON；客户端也必须捕获读取异常，失败后丢弃未完成文件。

当前普通下载的业务失败可能以 HTTP 200 返回 JSON，因此不能仅凭 HTTP 状态码或 curl 的 `--fail` 判断成功。先检查 `Content-Type`，JSON 应按错误响应处理，不能保存成视频。上述 curl 示例会把响应原样写入文件，手动调用时须结合 `download.headers` 检查结果；自动调用参考后文 Python 示例。

## 创建处理任务

请求为 JSON，未定义字段会被拒绝。`mode` 必填，其他字段按模式提供：

| 字段 | 默认值 | 约束 |
|---|---|---|
| `mode` | 无 | `zip`、`mux`、`concat`、`hls` 之一 |
| `url` | `""` | 主视频或清单地址，最多 8192 字符 |
| `audio_url` | `""` | 配套音轨地址，最多 8192 字符 |
| `urls` | `[]` | ZIP 或拼接的地址数组，最多 100 项，每项最多 8192 字符 |
| `filename` | `"media"` | 最多 180 字符；服务补充 `.zip` 或 `.mp4` 后缀 |

所有媒体地址应取自解析结果。接口不接受本地路径，网络请求和每次跳转均须通过服务端校验。

### 音视频合并

当所选视频 `requires_mux=true`，传入该项的视频地址和配套 `audio_url`。需要改选音轨时，从本次 `audio_backup` 中选择合适的实际音轨地址。

```bash
curl 'http://127.0.0.1:8848/api/download/jobs' \
  -H 'Content-Type: application/json' \
  --data '{"mode":"mux","url":"<视频地址>","audio_url":"<音轨地址>","filename":"combined"}'
```

### 图集或实况资源打包

```bash
curl 'http://127.0.0.1:8848/api/download/jobs' \
  -H 'Content-Type: application/json' \
  --data '{"mode":"zip","urls":["<照片地址>","<动态视频地址>"],"filename":"resources"}'
```

`urls` 必须非空；只有图片时直接传图片列表。ZIP 内资源按顺序编号，包含实际下载的原始文件。

### 多段视频拼接

```bash
curl 'http://127.0.0.1:8848/api/download/jobs' \
  -H 'Content-Type: application/json' \
  --data '{"mode":"concat","urls":["<第一段地址>","<第二段地址>"],"filename":"joined"}'
```

将 `segments` 按原顺序传入。拼接和合并采用流复制，依赖输入流与输出容器兼容；不保证任意编码组合均可合并，失败时任务返回 `failed`。

### 点播 HLS 合并

```bash
curl 'http://127.0.0.1:8848/api/download/jobs' \
  -H 'Content-Type: application/json' \
  --data '{"mode":"hls","url":"<点播m3u8地址>","filename":"vod"}'
```

支持有结束标记的未加密点播 HLS，以及主清单、独立音轨、初始化分片和字节范围。服务逐个验证和下载资源，再交给本地媒体程序处理；加密、DRM、无限直播和未验证嵌套清单会被拒绝。Linux 需要按部署指南显式配置系统 FFmpeg。

### 创建响应、进度与文件下载

创建成功使用 HTTP 200，响应示例：

```json
{
  "code": 200,
  "data": {
    "id": "服务生成的任务ID",
    "status": "queued",
    "stage": "等待下载",
    "filename": "combined.mp4",
    "downloaded_bytes": 0,
    "completed_items": 0,
    "total_items": 2
  }
}
```

后续操作：

```bash
curl 'http://127.0.0.1:8848/api/download/jobs/<任务ID>'
curl -X DELETE 'http://127.0.0.1:8848/api/download/jobs/<任务ID>'
curl --fail 'http://127.0.0.1:8848/api/download/jobs/<任务ID>/file' --output combined.mp4
```

| `status` | 含义 |
|---|---|
| `queued` | 已创建，等待执行 |
| `downloading` | 正在接收媒体 |
| `processing` | 正在打包或合并 |
| `completed` | 产物已生成，可下载 |
| `failed` | 失败，查看 `error`，不提供成功文件 |
| `cancelled` | 已取消，不继续生成结果 |

建议每秒查询一次。`downloaded_bytes` 为已接收的实际输入字节数，`completed_items` 为已完成资源数。HLS 会在展开清单时增加 `total_items`，任务进度不应直接当作固定比例百分数。

`completed` 响应新增 `download_url` 和 `data_size`；使用同一服务基础地址访问 `download_url`。`downloaded_bytes` 与合并后文件的 `data_size` 可以不同。服务完成处理不代表用户浏览器已保存文件，客户端仍需完成文件读取。

DELETE 取消活动任务并清理其临时文件；对已经完成、失败或取消的任务再次调用，返回当前状态，不会将已完成任务改成取消。任务文件和记录会在保留时间结束后清理，随后查询返回 404。服务重启后任务不能恢复。

## Python 调用示例

下面示例解析视频、按默认资源决定普通下载或处理任务，并检查 JSON 错误和文件长度。依赖项目已有的 `httpx`，将 `share_url` 换成实际作品链接。图集和实况使用上文 ZIP 流程。

```python
from pathlib import Path
import time
from urllib.parse import urlsplit

import httpx

base = "http://127.0.0.1:8848"
share_url = "https://www.bilibili.com/video/BV1GJ411x7h7/"
target = Path("download.mp4")
partial = target.with_name(target.name + ".part")

def api(response):
    response.raise_for_status()
    payload = response.json()
    if payload.get("code") != 200:
        raise RuntimeError(payload.get("msg", "接口调用失败"))
    return payload["data"]

with httpx.Client(base_url=base, timeout=300) as client:
    data = api(client.get("/api/parse", params={"url": share_url}))
    if data.get("type") != "video" or not data.get("url"):
        raise RuntimeError("本例只处理带默认视频地址的作品")

    # 可在此把 media 换成 data['video_backup'] 中明确选中的档位。
    media = data
    request = {"url": media["url"], "filename": "download"}
    if media.get("requires_concat"):
        request.update(mode="concat", urls=media["segments"])
    elif media.get("requires_mux"):
        request.update(mode="mux", audio_url=media["audio_url"])
    elif urlsplit(media["url"]).path.lower().endswith(".m3u8"):
        request.update(mode="hls")

    endpoint, params = "/api/download", request
    job_id = None
    try:
        if "mode" in request:
            job = api(client.post("/api/download/jobs", json=request))
            job_id = job["id"]
            deadline = time.monotonic() + 960
            while job["status"] not in {"completed", "failed", "cancelled"}:
                if time.monotonic() >= deadline:
                    raise TimeoutError("等待任务超时")
                time.sleep(1)
                job = api(client.get(f"/api/download/jobs/{job_id}"))
                print(job["stage"], job["downloaded_bytes"])
            if job["status"] != "completed":
                raise RuntimeError(job.get("error", job["stage"]))
            endpoint, params = job["download_url"], None

        if target.exists() or partial.exists():
            raise FileExistsError("目标文件或临时文件已存在，请更换文件名")
        started_file = False
        try:
            with client.stream("GET", endpoint, params=params) as response:
                response.raise_for_status()
                content_type = response.headers.get("content-type", "").lower()
                if not content_type.startswith(("video/", "audio/", "image/", "application/octet-stream")):
                    raise RuntimeError("下载返回非媒体响应，未保存文件")
                received = 0
                with partial.open("xb") as output:
                    started_file = True
                    for chunk in response.iter_bytes():
                        output.write(chunk)
                        received += len(chunk)
                expected = response.headers.get("content-length")
                if not received or (expected and received != int(expected)):
                    raise RuntimeError("文件未完整传输")
            partial.replace(target)
        finally:
            if started_file:
                partial.unlink(missing_ok=True)
    except BaseException:
        if job_id:
            client.delete(f"/api/download/jobs/{job_id}")
        raise
```

## 运行状态和开发诊断

```bash
curl 'http://127.0.0.1:8848/api/status'
```

此接口直接返回状态对象，外层没有 `code/data` 包装。字段包括 `status`、`supported_platforms`、`strategies`、`browser_available`、`download_features`、`cookie_status` 和 `cookie_configured`。会话状态为 `none`、`manual`、`auto_full`、`auto_partial` 或 `expired`；状态查询不会启动会话刷新。列入 `supported_platforms` 表示已实现对应路由，不是对每条作品链接的成功保证。

本地开发启用 `ENABLE_DEBUG_ENDPOINTS=1` 并重启后，可以调用：

```bash
curl --get 'http://127.0.0.1:8848/api/test' --data-urlencode 'aweme_id=<抖音作品ID>'
curl --get 'http://127.0.0.1:8848/api/debug' --data-urlencode 'aweme_id=<抖音作品ID>'
```

`aweme_id` 为必填的抖音作品 ID，不是媒体 `video_id`。`/api/test` 返回以策略名称为键的诊断对象，包含 `success` 及 `data` 或 `error`；`/api/debug` 返回提取的媒体字段，失败可能为 `{"error":"api_failed"}`。它们没有统一的业务响应包装，诊断字段不作为稳定的业务调用契约。

## 错误响应和调用者处理

当前不同接口的错误形态如下，调用者必须同时检查 HTTP 状态和实际响应：

| 场景 | HTTP / 响应 | 建议 |
|---|---|---|
| 解析成功 | HTTP 200，`code=200`，`data` 为资源对象 | 继续按资源类型处理 |
| 链接不支持或无法提取作品 ID | 通常 HTTP 200，JSON `code=400` | 检查分享地址，不自动改投其他平台 |
| 解析策略均失败 | 通常 HTTP 200，JSON `code=500` | 检查作品是否仍可访问，稍后重试 |
| 普通下载预检失败 | 可能 HTTP 200，JSON `code/msg` | 不将 JSON 写成媒体文件 |
| 任务参数业务错误 | HTTP 400，JSON `code/msg/data` | 修正模式和必需资源 |
| 路由参数或 JSON 模型错误 | HTTP 422，FastAPI `detail` 列表 | 按字段位置修正请求 |
| 任务不存在、过期或服务已重启 | HTTP 404，JSON `code=404` | 重新创建任务 |
| 文件未准备好 | HTTP 409，JSON `code=409` | 查询任务状态，不下载未完成文件 |
| 任务数量达到上限 | HTTP 429，JSON `code=429` | 延迟重试，避免持续创建任务 |
| 任务下载、合并或依赖失败 | 查询通常仍为 HTTP 200、`code=200`，但 `data.status=failed` | 查看 `error`，重新解析或分别下载 |
| 普通下载超过体积、Range 无效或上游拒绝 | 普通下载 JSON `code` 可能为 413、416 或上游状态 | 检查实际响应，调整请求 |
| 下载开始后连接中断或字节数不足 | 流读取异常或不完整文件，未必有 JSON | 删除临时文件后重试 |
| 诊断接口未启用 | HTTP 404，`detail` 描述 | 仅在本地开发按需启用 |

示例业务错误为 `{"code":400,"msg":"链接格式无效或暂不支持该平台","data":null}`。不要依赖固定的 `msg` 文本作分支；优先使用接口类型、`code` 和任务 `status`。

## 上限和开发验证范围

当前每进程最多 3 个活动任务、20 个保留记录；普通打包和拼接最多 100 个输入，每个 HLS 媒体清单最多 500 个分片，独立音轨清单分别计算。整个任务仍受下载上限 4 GiB、执行上限 15 分钟约束，结束后保留记录 10 分钟，成功产物在保留期内可取。任务状态在进程内，部署必须使用单 worker。

本轮 Windows 自动化测试 236 项通过；Linux GitHub Actions 在显式使用系统 FFmpeg 后也为 236 项通过。真实抖音下载和 B站分离流合并已验证；小红书实站效果、真实 2K/4K 作品专项下载和浏览器直接写磁盘选择器仍有单独的未验证边界，不能由结构样本测试替代。详细测试命令和记录见 [解析原理与开发测试](解析原理与开发测试.md)。
