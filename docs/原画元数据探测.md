# 原画元数据探测

## 目标与数据约定

原画地址完成 HEAD 验证后，尽力读取 MP4 自身的元数据。宽高、编码、帧率和码率不得借用其他转码档；读取失败时保留可用直链，原画未知参数继续为 0 或空字符串。媒体请求和播放量请求沿用各自现有 UA。

- `width`、`height`：视频样本描述中的像素宽高；`rotation` 单独记录视频轨旋转，不混淆编码尺寸和显示方向。
- `codec`：归一化编码，`h264`、`h265`、`av1` 等；`codec_tag` 保留 `avc1`、`hvc1` 等原始标记。
- `fps`：按视频解码时间表计算的平均帧率，`fps_kind=average`；不将平均值声明为固定帧率。
- `duration`：优先采用容器播放时长，缺少时使用视频轨时长，单位毫秒；`video_duration` 单独记录视频轨媒体时长。
- `bitrate` / `bit_rate`：只有视频采样大小与时间表足以确定时才填写视频轨平均码率，`bitrate_kind=video_average`。
- `overall_bitrate`：根据整个文件大小与容器时长计算的整文件平均码率，包含音频和容器开销，不等同于视频编码码率。
- `metadata_source=mp4_moov`：标记已从媒体结构取得有效字段；部分字段缺失时仅补充已确认的值。

## 模块与读取流程

`original_metadata.py` 拥有纯 MP4 结构解析、Range 读取规划、资源预算与缓存。完整后端和 Workers 仅提供各自的网络读取适配器；构建脚本将同一个模块带入 Worker。本地开发显式监听入口、共享解析模块及网页，源码变化后重建运行包。

先读取小段文件头，按顶层 box 的声明长度跳过 `mdat` 等数据段，定位 `moov`。需要时对齐偏移补读完整元数据 box，不扫描视频负载中的任意 `moov` 字符串。支持文件头和文件尾布局、64 位 box 长度、时间字段版本与多个音视频轨。

Range 响应必须为 206，且范围、总文件长度、声明体积和实际接收量一致。每次跳转继续执行现有媒体主机检查；后续请求使用可用的文件验证标记，避免混合不同版本。上游忽略 Range 时立即结束元数据探测，不读取其完整响应体。

媒体候选列表可能包含 `www.douyin.com` 的第一方跳转入口。Workers 与完整后端均支持这类入口，仍逐跳检查最终媒体主机；不将第一方 302 条目直接当作已验证的 CDN 文件。

读取具有请求数、总字节、单个 box、表项及总时间上限；完成结果仅作短期有界内存缓存，缓存身份包含实际媒体地址、文件长度和可用的文件验证标记，不持久化凭据或媒体文件。Workers 使用更小的预算和表项上限，超出时保留已确认字段或回到未知值。

| 预算 | 完整后端 | Workers 测试入口 |
|---|---|---|
| Range 请求数 | 最多 4 次 | 最多 3 次 |
| 默认读取窗口 | 64 KiB | 32 KiB |
| 单个 moov | 最多 4 MiB | 最多 256 KiB |
| 累计响应字节 | 最多 4 MiB + 64 KiB | 最多 512 KiB |
| 元数据总时间 | 5 秒 | 4 秒 |
| 解码时间表项 | 最多 16,384 | 最多 256 |
| 元数据 box 总数 | 最多 4,096 | 最多 256，跨所有层级累计 |
| 逐样本大小表 | 最多 200,000 项 | 不遍历；固定样本大小可直接计算 |

缓存最多 64 个成功结果，保留 5 分钟。HEAD 提供验证标记时用于缓存身份与 `If-Range`；未提供时仅作短期缓存。Range 请求仍受原有逐跳网络检查约束。

分片 MP4 的时间表可能不完整，不能仅凭初始化 `moov` 推导完整帧率和视频码率。超限、截断、异常尺寸、无有效视频轨或不支持的结构均按尽力探测处理。

## 开发验证

验证覆盖正常和尾部布局、扩展 box、超过 4 GiB 的偏移、窗口边界、变帧率、音频优先的轨道顺序、旋转、采样大小、坏数据、请求预算、Range 不支持或不一致、版本变化、失败保留直链，以及页面对平均帧率和整文件平均码率的标注。真实生成的 H.264、H.265 MP4 分别验证了头部和尾部元数据布局。

本轮完整自动化测试 `294` 项通过，耗时 `20.81` 秒；Python 模块编译及变更空白检查通过。真实浏览器核对了原画自身的分辨率、H.265 编码、平均帧率与整文件平均码率，390px 布局没有横向溢出。

本轮对同一条公开视频的原画进行独立读取，结果为 `1280×720`、`hvc1 / H.265`、平均 `30 fps`，容器时长 `11,169 ms`、视频轨时长 `11,100 ms`。视频轨平均码率为 `1,615,640 bit/s`，整文件平均码率为 `1,742,121 bit/s`，证明两个字段不能混用。

完整后端实际读取范围为 `0–65535` 和 `2420450–2432218`，合计 `77,305` 字节；相同地址、长度和验证标记的重复探测没有新增 Range 请求。Workers 真实本地运行时也取得相同的编码、尺寸、平均帧率和容器时长；受较小采样表预算约束，本次仅返回整文件平均码率，视频轨码率保持未知。

新增元数据处理的 Workers 云端 CPU 与线上新版本尚待验证，不以本地运行时结果替代免费云端限制验证。真实 2K/4K 平台作品的专项复核仍需可访问样本，结构测试中的 2K/4K 数据不作为实站结果。
