# 抖音解析接口依据与约定

更新依据：[抖音原画解析接口](https://linux.do/t/topic/3041970)，核验日期：2026-10-19。

## 已核验的上游行为

帖子列出的接口属于抖音站点内部接口，未找到承诺其长期稳定性的官方开放 API 文档。此次依据直接请求上游的结果接入，保留已有失败处理策略。

- `GET https://www.douyin.com/aweme/v1/web/aweme/detail/`：传入 `aweme_id`、`aid=6383`、`device_platform=webapp`，带 `Origin: https://open.douyin.com`、`Referer: https://open.douyin.com/`。两条公开作品均在未发送 Cookie 时返回 `status_code=0` 和 `aweme_detail`。
- `HEAD https://aweme.snssdk.com/aweme/v1/play/?video_id=<video.play_addr.uri>&ratio=default&line=0`：实际返回 302；跳转后的 CDN 在携带抖音 Referer 时返回 `video/mp4` 和文件大小。作品 ID 与媒体 `video_id` 不能混用。
- `GET https://jingxuan.douyin.com/m/video/<作品ID>?app=yumme`：使用移动端 UA、`curl_cffi` 的 Chrome TLS 指纹可读取 `window._SSR_DATA.data.storeState.detail.videoData.result.play_count`。须核对同一对象的 `gid`，不能匹配推荐视频的计数。本机普通 HTTP 客户端曾返回 404。

## 项目实现约定

- `douyin_parser.py` 统一格式化详情、转码档和精选页计数；浏览器与 API 策略共用同一格式化逻辑。
- `server.py` 负责网络请求、策略顺序、媒体 HEAD 探测和响应组装；不增加依赖、不持久化上游响应、不需要新增凭据。
- 解析顺序为免 Cookie 详情、签名详情、浏览器拦截、第三方公开 API。免 Cookie 请求不得附带本地 Cookie。
- 保持 `/api/parse` 的请求方式和响应外层结构。`url` 默认优先使用通过 HEAD 验证的原画 CDN；探测失败时保留已获得的无水印转码链接。
- `original_url` 为 `ratio=default` 的原画入口；`video_backup` 保留所有可用转码档及备用 URL、宽高、文件字节数、帧率、码率、编码、容器格式。最高码率转码不能称为原画。
- 网页首先显示经验证的原画或默认转码下载，再展示全部具有独立链接的转码档。画质名称从宽高或可识别的画质字段生成，4K / 2K 分别对应短边 2160 / 1440 像素；同画质、同编码但码率不同的条目不会按名称合并。每档保留独立的下载链接和含标题、画质、编码、码率的文件名。
- `quality=original` 仅在原画探测成功时设置。HEAD 无法证明原画的宽高、帧率或码率，因此这些值使用 0 表示未知，不能沿用某个转码档的数值；`data_size` 以实际 HEAD 响应为准。
- 播放量是尽力获取的可选字段 `play_count`。上游失败或未给出有效计数时省略，真实的 0 保留；图集不查询精选视频页。
- 媒体探测只读响应头、限制耗时和跳转次数，每一跳必须通过既有公网地址校验，拒绝 HTML 错误页。所有请求保留超时；播放量不可用不影响视频解析成功。
- 本机真实 DNS 返回 `198.18.0.13` / `2001:2::88` 等代理 Fake-IP 映射。公网校验仅对 `aweme.snssdk.com`、`*.douyinvod.com`、`*.zjcdn.com` 的 HTTPS 默认端口识别 `198.18.0.0/15`、`2001:2::/48`；普通域名、相似域名、IP 字面量、非默认端口和其他私网/保留地址不适用此规则。原画探测和下载代理共用该校验。

## 验证与范围

用自动化测试覆盖画质格式、原画失败后的转码保留、无 Cookie 请求、异常响应、播放量定位和不安全跳转；用真实公开作品核验原画 HEAD 和解析返回。原画入口不承诺一定高于上传分辨率，也不承诺每个作品都有 4K。

真实 `/api/parse` 请求已分别取得 7 档、19 档转码和有效播放量，两条均选择验证成功的原画 CDN。原画 HEAD 大小分别为 2,432,219 与 1,373,458,318 字节；另以 Range GET 读取首个 1024 字节，确认返回 206、`video/mp4` 和 MP4 文件头，没有完整下载大文件。

后端验证：50 项自动化测试通过，覆盖仅媒体 ID 且原画探测失败时继续后备策略、附件响应和私网重定向拒绝；相关 Python 模块编译与 `git diff --check` 通过。真实下载代理返回 200、`video/mp4`，读取首个 65,536 字节确认 MP4 文件头后关闭流。

页面验证：新增 5 项 Chromium 测试，覆盖全部画质展示、参数、所选画质的实际下载请求、移动端宽度、键盘操作、原画不可用状态和上游标签 HTML 注入。修改前曾以 7 档测试数据复现只出现 6 个下载按钮（原画 + 5 档转码），修改后保留全部 8 个按钮。CI 增加 Chromium 与系统依赖安装。

全套共 55 项测试通过。另启动本地服务进行真实 Chromium 端到端验证：解析公开视频后页面完整显示 7 档转码，点击指定转码成功下载 2,395,049 字节 MP4，文件头有效、无页面脚本错误；移动端无横向溢出。该验证仅替换状态查询以避免刷新本地 Cookie，解析和下载均请求真实上游。

本次更新解析后端、页面画质下载、相关测试及说明文档；不改变其他平台的解析策略、依赖版本或部署方式。
