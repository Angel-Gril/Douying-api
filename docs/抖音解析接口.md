# 抖音解析逻辑

本文件只描述本项目的实现和验证，不作为外部项目说明。

## 策略顺序

1. 获取公开作品详情，保留实际返回的视频、画质、图集和实况资源。
2. 未取得有效资源时，使用与设备参数和会话一致的签名请求。
3. 需要时通过本地浏览器读取详情。
4. 仍失败时进入统一备用适配器。

任何策略只有取得有效媒体资源才算成功；只有媒体 ID、没有可用转码且原画探测失败时，继续下一策略。

## 原画与转码

作品 ID 用于取得详情，`video.play_addr.uri` 中的媒体 ID 用于播放入口。构造播放参数 `video_id=<媒体ID>&ratio=default&line=0`，用 HEAD 展开重定向并验证最终媒体类型和大小。

`video.bit_rate[]` 是转码档，保留全部可用项与同档备用地址，按实际码率排列。最高码率转码不等于原画。原画不可用时继续返回可用转码。

原画 HEAD 成功后，通过有界 Range 读取 MP4 自身的 `moov`，补充分辨率、编码、平均帧率和时长。视频轨平均码率与整文件平均码率分开记录；缺失或探测失败的原画字段保持未知，不套用转码档参数。读取方法、预算与测试见 [原画元数据探测](原画元数据探测.md)。

## 会话与签名

请求 UA、签名 UA、屏幕和平台参数使用同一份设备信息。TLS 指纹从本地库实际支持的列表选择。会话中的设备字段按需进入请求，不写到日志或页面配置。

自动会话刷新共享锁，避免并发启动多个浏览器。已配置的手动会话直接使用，其失败不删除其他自动缓存。状态查询只读取已有状态，调试入口与正常解析共用签名构造。

## 图集、实况与统计

图集保留图片地址；实况保留图片和动态视频的对应关系。统计只保存实际上游数字；播放量的补充查询失败不影响已经取得的媒体结果。

## 验证

自动测试覆盖全部画质、有效资源判定、原画失败回退、实况配对、身份参数一致性、并发刷新、状态查询和下载边界。真实浏览器已完成公开作品的原画下载；详细验证结果见《解析原理与开发测试》和实施回写。
